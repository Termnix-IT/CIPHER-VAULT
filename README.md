# CIPHER VAULT

端末内でパスワードを管理する、ローカルファーストのアプリです。Electronデスクトップ版とWeb/API版があり、保管庫データは自端末のSQLiteに保存します。

従来形式ではパスワードとメモをAES-256-GCMで暗号化し、サービス名・ログインID・URL・タグ・グループ・日時は平文で保存します。v0.3.0以降の[保管庫の更新](#保管庫の更新マスターパスワードの変更空にする)で新形式へ移行すると、移行先では全項目を暗号化します。保持する元の保管庫の保存内容と暗号化方式は変わりません。保管庫データは外部へ送信しません。手動の更新確認・ダウンロード時にはGitHubに接続します。画面のフォントはライセンスとともに同梱し、外部通信なしで読み込みます。

## 入手・起動

Windows用の実行ファイルは [GitHub Releases](https://github.com/Termnix-IT/CIPHER-VAULT/releases) から入手します。配布版の利用にNode.jsやnpmのインストールは不要です。

| 配布形式 | 起動方法・用途 |
|---|---|
| `CIPHER-VAULT-<version>-x64-setup.exe` | インストールして利用する通常向けの版。アプリ内から手動更新できます |
| `CIPHER-VAULT-<version>-x64-portable.exe` | インストールせず実行する版。更新は配布ページから入手します |

どちらもデータはElectronの `userData/data/` に保存します。portable版もexeの隣にDBを保存する方式ではなく、exeを移動するだけでは保管庫データを移せません。別端末への移行には[暗号化バックアップ](#暗号化バックアップと復元)を使います。

ソースコードからの起動は[開発する場合](#開発する場合)を参照してください。

## 主な機能

- マスターパスワードによる保管庫の作成・解除・ロック
- ログインの登録、編集、削除。v0.3.0以降は新形式の保管庫でAPIキー・クレジットカードも種類別に登録
- サービス名・ログインID・グループ・タグの検索とグループ表示
- パスワード生成とログインID・パスワード・URLのコピー
- 共通サービス側で強制する、5分間操作がない場合の自動ロック
- 全項目を暗号化した `.cvault` バックアップと空の保管庫への復元（v0.2.2以降）
- ログインのパスワードの弱さ・使い回しなどを端末内で調べるパスワードの点検（v0.2.2以降）
- setup版での手動アップデート

## 基本操作と画面

以下の画像はデスクトップ版の画面です。表示している値はすべてテスト用です。左に一覧、右に詳細を表示し、「編集」で入力欄に切り替えます。バックアップとパスワードの点検は「ツール」から開きます。

### 1. 保管庫を設定・解除する

初回起動時は、12文字以上のマスターパスワードを2回入力し、「保管庫を作成」を押します。次回以降は同じパスワードを入力し、「開く」を押します。

マスターパスワードは復元できません。従来形式の[完全リセット](#マスターパスワードを忘れた場合)では、保存済みデータが削除されます。新形式で保管庫を空にするには、今のマスターパスワードが必要です。

![マスターパスワードを入力して保管庫を開くロック画面](docs/images/ロック解除.png)

### 2. 項目を登録する

1. 左上の検索欄の横にある「＋」を押します。
2. v0.3.0以降は上部のタブで「ログイン」「APIキー」「カード」を選びます。ログインはサービス・ログインID・パスワードが必須で、URLは任意です。
3. グループ・タグ・メモを付ける場合は「＋ グループ・タグ・メモを追加」を押します。タグはカンマで区切ります。
4. ログインの「生成」を押すと、大文字・小文字・数字・記号を含む20文字のパスワードが入力されます。
5. 右下の「保存」を押します。

APIキー・カードは、全項目を暗号化する新形式の保管庫で使用します。従来形式では入力画面の「保管庫を更新」から[保管庫の更新](#保管庫の更新マスターパスワードの変更空にする)へ進みます。保存済みの種類は変更できません。

| 種類 | 必須項目 | 任意項目 |
|---|---|---|
| APIキー | 名前、キー | キーID、有効期限、URL、グループ、タグ、メモ |
| カード | 名前、カード番号 | 名義、有効期限（月）、セキュリティコード（3〜4桁）、URL、グループ、タグ、メモ |

キーは空白を含めてそのまま保存します。カード番号は空白・ハイフンを除いた12〜19桁で保存し、暗証番号は扱いません。一覧にはカード番号の末尾4桁だけを表示します。キー・カード番号・セキュリティコードは伏せ字で扱い、各項目の目のアイコンを2回押して表示し、個別にコピーできます。これらの秘密値は検索対象に含めません。Codex向けMCP候補検索ではAPIキーの名前と接続先のoriginを扱い、カードを除外します。

![新しい項目の入力欄にテスト用の情報を入力した画面](docs/images/新規エントリ.png)

### 3. 詳細を確認・編集する

左の一覧から項目を選ぶと、右側に詳細を表示します。値が空の欄は表示しません。ログインID・パスワード・URLは各コピーボタンでクリップボードへコピーできます。パスワードは通常伏せ字で表示します。目のアイコンを3秒以内に2回クリックすると表示され、表示中は1回クリックで隠せます。キーボードでもアイコンを選択してEnterまたはSpaceを2回押すと表示できます。保存・生成・閲覧と編集の切り替え・項目の切り替え・ロック時には伏せ字へ戻ります。

右上の「編集」、またはメニューの「編集」→「選択中の項目を編集」で入力欄に切り替えます。欄の位置は閲覧時と同じです。値を変更して「保存」を押すと更新し、閲覧に戻ります。「キャンセル」は未保存の変更があれば破棄を確認して閲覧に戻ります。「生成」は入力欄のパスワードを置き換えるため、保存前に内容を確認してください。削除は編集中に左下の「削除」から実行します。保存・キャンセルは右下に固定され、入力欄が収まらない場合は詳細部分をスクロールできます。

![項目の一覧と選択したテスト用項目の詳細・編集フォーム](docs/images/エントリ詳細.png)

### 4. 検索・グループ表示・ロック

- 左上の検索欄で、サービス名・ログインID・グループ・タグを絞り込めます。検索中は検索欄に「該当件数 / 全件数」を表示します。
- 「表示」→「すべて／グループ別」で表示を切り替え、グループ名で折りたたみます。
- 「ファイル」→「一覧を更新」で一覧を読み直します。アプリの更新は「ヘルプ」→「バージョンと更新」から行います。
- 作業を終えるときは左下の「ロック」、または「ファイル」→「ロック」を選びます。未保存の変更があれば破棄の確認を表示します。5分間操作がない場合も自動ロックされるため、入力中の内容は保存してください。Electron版はOSの画面ロック・スリープ・復帰通知でもロックし、保管庫の再解除が必要です。
- Electron版でコピーした内容は30秒後、または保管庫ロック時に自分のコピーと一致すれば消去します。後から別の内容をコピーした場合は保持します。OSの履歴や同期済みコピー、Web版は対象外です。[動作条件](docs/設計.md#electronのosイベントとクリップボード)を参照してください。

自動ロックは画面のタイマーではなく、保管庫を扱う共通サービス側で実行します。一覧の再取得や状態確認だけでは期限を延長しません。Electronはウィンドウを閉じた場合や画面プロセスが失われた場合もロックします。Webは状態確認で画面に反映し、接続状態を確認できない場合は表示中の秘密を消して再解除を求めます。

## 暗号化バックアップと復元

バックアップにはサービス名・ログインIDを含む全項目が暗号化されて入ります。マスターパスワードは含まれず、読み込みには書き出し時のバックアップ用パスワードが必要です。編集中の場合は保存してから「バックアップ」を開きます。

### 書き出す

1. 保管庫を解除し、「ツール」→「バックアップ」を選びます。
2. 「書き出す」タブで、バックアップ用パスワード（12文字以上）を2回入力します。
3. 「N件を書き出す」を押し、保存先に `.cvault` ファイルがあることを確認します。
4. ファイルとバックアップ用パスワードは別々の安全な場所に保管します。

### 読み込む（復元する）

1. 復元先でマスターパスワードを設定して保管庫を解除します。読み込めるのは項目が0件の保管庫だけです。
2. 「ツール」→「バックアップ」を開き、「読み込む」タブで `.cvault` ファイルを選びます。
3. 書き出し時のバックアップ用パスワードを入力し、「読み込む」を押します。
4. 読み込んだ項目を確認します。その後の解除には復元先のマスターパスワードを使います。

APIキー・カードを含むバックアップは新形式の空の保管庫へ復元します。新しいバックアップ形式と種類別保存に未対応の旧版アプリでは読み込めません。ログインだけのバックアップは従来のv1形式を維持し、既存のバックアップも復元できます。

既存データへの追加・置き換えは行いません。バックアップは10,000件・暗号化前の内容11 MiB、読込ファイル16 MiBまで対応します。形式と互換性は[設計](docs/設計.md)を参照してください。

## 保管庫の更新・マスターパスワードの変更・空にする

v0.3.0以降で利用できます。新規の保管庫は従来形式で作成し、新形式への移行は「保管庫を更新」から明示的に行います。

1. 保管庫を解除し、編集中の内容を保存してから「ツール」を開きます。
2. 従来形式では「保管庫を更新…」、新形式では「マスターパスワードを変更…」または「保管庫を空にする…」を選びます。
3. 今のマスターパスワード、新しいマスターパスワード（2回）、復旧用パスワード（2回）を入力します。新しいマスターパスワードと復旧用パスワードは12文字以上です。復旧用パスワードは、変更が途中で止まったときに元に戻すために使います。保管庫を空にする場合は確認欄も選択します。
4. 照合と切替が完了したら画面を閉じ、新しいマスターパスワードで解除します。解除後は[暗号化バックアップ](#暗号化バックアップと復元)を端末外にも書き出してください。

更新とマスターパスワードの変更では全項目を新しい鍵で再暗号化します。保管庫を空にする操作は新しい鍵の空Vaultへ切り替える操作で、安全な消去ではありません。元の保管庫と復旧用ファイルは端末内に残り、以前のパスワードで復号できるデータも保持します。移行後は対応する版のアプリで利用し、旧版で元の保管庫を編集しないでください。旧版の編集は移行先へ反映されません。

処理中は「中止」を使います。中止後も、安全に停止するまで待ってください。切替の完了確認が必要な場合は「前回の変更を完了させてください」の画面を自動表示し、通常の解除・編集を停止します。変更前と変更時に決めたマスターパスワード、復旧用パスワードを入力して「完了させる」を実行します。元のファイルを削除・置換して回避しないでください。Windowsの電源断時の永続化など、残る条件は[設計](docs/設計.md#保管庫の管理サービスと復旧専用起動)を参照してください。

## パスワードの点検

保存後に「ツール」→「パスワードの点検」を開くと、推測されやすいパスワード・使い回しを「直したほうがいい」、1年以上変更なし・URLなし・1年以上更新なしを「余裕があれば見直す」として端末内で調べます。件数を押すと絞り込み、「開く」から対象を編集できます。変更後は「もう一度点検」を押します。

スコアは弱さと使い回しから算出する目安です。古さ・URLなし・長期間更新なしは減点しません。古さと長期間更新なしの目安は365日で、旧データのパスワード変更日は不明として扱います。外部の漏えい情報への照会は行わず、スコアは安全性を保証するものではありません。判定の詳細は[設計](docs/設計.md)を参照してください。

## アプリを更新する

Windowsのsetup版では「ヘルプ」→「バージョンと更新」から確認・ダウンロードし、「再起動して更新」でインストーラーの操作なしに更新できます。OSの権限確認が出る場合があります。起動時の確認や通常終了時の自動適用はありません。その他の配布形式は配布ページから入手します。

更新機能のない旧版からは、アプリを終了して新しいsetupを同じインストール先へ上書きします。詳しくは[手動更新とアイコン](docs/手動更新とアイコン.md)を参照してください。

## マスターパスワードを忘れた場合

従来形式では、ロック画面の「パスワードを忘れた場合」から、データ消失の確認と確認コードの手入力を経て完全リセットできます。**保存済みの項目と保管庫設定はすべて削除されます。** マスターパスワードを復旧する操作ではありません。新形式ではこの完全リセットを表示せず、今のマスターパスワードで解除してから「保管庫を空にする…」を使います。

事前に書き出した `.cvault` とそのバックアップ用パスワードがある場合は、新しいマスターパスワードを設定した空の保管庫へバックアップ時点の内容を読み込めます。

## 開発する場合

開発にはNode.js 22.12.0以上とnpmを使用します。Windows用配布物の生成にはWindowsとPowerShellが必要です。Web/API版の開発はWindows・macOS・Linuxを対象としています。

リポジトリルートで実行します。

```powershell
npm install
npm run dev:desktop
```

| コマンド | 用途 |
|---|---|
| `npm run dev` | Web（`http://localhost:5173`）とAPI（`http://localhost:3001`）を起動 |
| `npm run dev:desktop` | ViteとElectronで開発起動 |
| `npm run build` / `npm run start` | Web/APIをビルドし、`http://localhost:3001` で起動 |
| `npm run build:desktop` / `npm run start:desktop` | デスクトップ版をビルド・起動 |
| `npm run package:desktop` | `dist-desktop/` にWindows用setup・portableを生成（公開しない） |
| `npm run package:desktop:linux` / `npm run package:desktop:mac` | 対象OS上でLinux / macOSの評価用パッケージを生成（公開しない） |
| `npm run package` | Node.jsで動かすWeb/API配布フォルダ `release/` を生成 |

検証コマンドは[変更に応じた検証](docs/開発・配布手順.md#変更に応じた検証)から選びます。開発・テストで利用中の保管庫を初期化・上書きしないでください。構成・通信・暗号化は[設計](docs/設計.md)、保存先・配布・CIは[開発・配布手順](docs/開発・配布手順.md)を参照してください。Linux/macOSのパッケージは評価用です。
