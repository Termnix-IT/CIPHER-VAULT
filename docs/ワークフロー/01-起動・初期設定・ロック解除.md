# 1. 起動・初期設定・ロック解除

アプリ起動から保管庫の初期設定またはロック解除を経て、ダッシュボードを表示するまでの状態遷移です。

```mermaid
flowchart TD
    start([アプリ起動]) --> mount[React Appをマウント]
    mount --> status[保管庫状態を取得]
    status --> configured{保管庫は設定済みか}

    configured -- いいえ --> setupScreen[初期設定画面を表示]
    setupScreen --> setupInput[マスターパスワードを入力]
    setupInput --> setupValid{12文字以上か}
    setupValid -- いいえ --> setupError[入力エラーを表示]
    setupError --> setupInput
    setupValid -- はい --> setupGate[共有実行枠・待機期限を確認]
    setupGate --> deriveSetup[Salt生成・保管庫鍵を非同期導出]
    deriveSetup --> setupEpoch{開始時と同じ世代か}
    setupEpoch -- いいえ --> cancelled[一時鍵を破棄し要求を取消]
    setupEpoch -- はい --> saveMetadata[(検証値を作りvault_metadataへ保存)]
    saveMetadata --> keepKey[保管庫鍵をメモリに保持]
    keepKey --> unlocked

    configured -- はい --> unlockedCheck{ロック解除済みか}
    unlockedCheck -- いいえ --> unlockScreen[ロック解除画面を表示]
    unlockScreen --> unlockInput[マスターパスワードを入力]
    unlockInput --> unlockGate[共有実行枠・待機期限を確認]
    unlockGate --> deriveUnlock[保管庫鍵を非同期導出]
    deriveUnlock --> unlockEpoch{開始時と同じ世代か}
    unlockEpoch -- いいえ --> cancelled
    unlockEpoch -- はい --> verify[導出鍵から保存済み検証値を検証]
    verify --> verified{一致するか}
    verified -- いいえ --> unlockError[認証エラーを表示]
    unlockError --> unlockInput
    verified -- はい --> legacy{旧形式の検証値か}
    legacy -- はい --> migrate[HMAC検証値へ移行]
    migrate --> keepKey
    legacy -- いいえ --> keepKey

    unlockedCheck -- はい --> unlocked[ロック解除状態]
    unlocked --> list[エントリ一覧を取得]
    list --> dashboard[ダッシュボードを表示]

    dashboard --> activity{ユーザー操作あり}
    activity -- はい --> resetTimer[現在の世代でCoreへ操作通知]
    resetTimer --> dashboard
    activity -- 5分間なし --> autoLock[Coreのタイマーまたは操作入口で失効]
    dashboard -->|手動ロック| manualLock[手動ロック]
    autoLock --> clearKey[メモリ上の保管庫鍵を破棄]
    manualLock --> clearKey
    clearKey --> invalidate[世代変更を通知し旧応答と表示を破棄]
    invalidate --> unlockScreen
```

## 対応する主なコード

- `apps/web/src/App.tsx`: 起動時の状態取得、画面切り替え、人の入力通知とロックの画面反映
- `apps/web/src/pages/LockScreen.tsx`: 初期設定・ロック解除フォーム
- `apps/api/src/services/vault-service.ts`: 初期設定、検証、セッション操作
- `apps/api/src/services/vault-session.ts`: 鍵・解除状態・世代・5分期限の一元管理
- `apps/api/src/services/vault-unlock-guard.ts`: 初期設定・解除の同時実行と認証失敗時の待機制御
- `apps/api/src/services/crypto-service.ts`: Salt、検証器、保管庫鍵の導出
- `apps/electron/src/vault-power-guard.ts`: OS通知とロック中のIPC拒否
- `apps/electron/src/expiring-clipboard.ts`: コピーの期限とロック時の条件付き消去
- `apps/api/src/services/vault-store.ts`: `vault_metadata` の読み書き

## 状態に関する注意

- `isConfigured` はSQLiteに `vault_metadata` が存在するかで決まります。
- `isUnlocked` は `VaultSession` 内の鍵の有無と期限から決まり、プロセスのメモリ上だけで管理されます。
- 通常APIや状態確認だけでは期限を延長しません。期限後の操作通知は再解除にならず、拒否されます。
- 初期設定・解除は1件ずつ実行し、導出中のロック・リセットで取り消します。5回連続の誤パスワードから待機を増やします。具体的な上限と保持条件は[設計](../設計.md#マスターパスワード)を参照してください。
- ElectronはOSの画面ロック/解除・スリープ/復帰の対応通知、ウィンドウ終了・renderer喪失でもロックします。復帰による自動解除は行いません。状態通知またはWebの定期確認で画面を追従させます。
- アプリまたはAPIプロセスを再起動すると、設定済みでもロック状態に戻ります。
- v0.2.1の修正では検証値を保管庫鍵と分離します。旧形式の移行は認証成功後のみ行い、移行後は旧版へ戻せません。過去のDBコピーに残る鍵は無効化されません。[移行の制約](../リリースノート/v0.2.1.md)を参照してください。
