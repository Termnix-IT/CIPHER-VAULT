# 開発・配布手順

リポジトリルートで実行します。アプリの使い方は[README](../README.md)、公開操作は[リリース手順](リリース手順.md)を参照してください。

## 前提条件

- OS: Windows（開発・配布ともWindowsだけを対象とする）
- Node.js: `22.12.0` 以上（Viteが要求するため）とnpm。画面（`apps/web`）のビルドと、試験・配布のスクリプトに使います
- Rust（stable）とMSVCのビルドツール。Cargo workspaceはリポジトリルートの `Cargo.toml` で、`target/` に生成物を置きます
- Microsoft Edge WebView2（Windows 11には標準で入っています）

依存関係が未導入の場合は最初に実行します。

```powershell
npm install
```

## 構成

| 場所 | 役割 |
|---|---|
| `crates/vault-core/` | 中核です。Tauriに依存しないので、画面なしで試験できます。暗号形式（`.cvault`、v2のenvelope）、v2の保存、保管庫の選択、セッション、入力検証、初期設定・解除・ロック、エントリ操作、パスワード生成、バックアップの書き出しと復元、パスワードの点検（監査）、保守（既存形式からv2への移行、v2の鍵更新とリセット、途中で止まった切り替えの復旧）を持ちます |
| `apps/desktop/` | Tauriのデスクトップアプリです。`apps/web` のビルド結果（`apps/web/dist-tauri`）を埋め込み、`window.passwordManager` を `src/desktop-api.js` で用意します。クリップボード、画面ロック・スリープとの連動、多重起動の防止、署名付きの手動更新、Electron版の起動中の拒否もここが受け持ちます |
| `apps/web/` | React + Viteの画面です |
| `packages/shared/` | 画面が使う共通の型と、画面のCSP |

Electron版（`apps/electron`）とNode.jsのサービス（`apps/api`）、Web/API版はv0.9.0の後に削除しました。必要な場合はgitのタグ `v0.9.0` から参照できます。

## 起動する

画面をビルドしてから、試験用のフォルダを指定して起動します。**手で動かすときは必ず `CIPHER_VAULT_DATA_DIR` に試験用のフォルダを指定してください。** `cargo run` のビルドは `e2e` 機能なしの通常ビルドなので、指定を忘れるとこの端末で使っている保管庫を開きます。起動を拒否したときの理由は標準エラーとダイアログに出ます。

```powershell
npm run build:web
New-Item -ItemType Directory -Force "$env:TEMP\cipher-vault-rust-data"
$env:CIPHER_VAULT_DATA_DIR = "$env:TEMP\cipher-vault-rust-data"
cargo run -p cipher-vault
```

画面だけを変えた場合も、`npm run build:web` で作り直してから起動します。開発サーバーとホットリロードはありません。

## データ保存先

保管庫は `%APPDATA%\<製品名>\data`（配布版は `%APPDATA%\CIPHER VAULT\data`）に保存します。Electron版と同じ場所なので、移行しても保管庫は動きません。環境変数 `CIPHER_VAULT_DATA_DIR` に既存フォルダの絶対パスを指定すると、そのフォルダを代わりに開きます。

`e2e` 機能付きのビルドは、製品名が「CIPHER VAULT」のままでは既定の保存先を開きません。`CIPHER_VAULT_DATA_DIR` に `%APPDATA%` の下・`apps\api\data`・`release\data`（Web/API版の保存先だった場所）を指定しても起動しません。

DB接続は起動処理が明示的に開きます。未知形式や読取専用で検査できないDBでは、初期化せず停止します。DBや `-wal` / `-shm` / `-journal` を削除して再試行せず、原本を保持してください。形式判定の条件は[DBの接続と形式判定](設計.md#dbの接続と形式判定)を参照してください。

## 配布物を作る

```powershell
npm run package:tauri
```

`dist-tauri/` にsetup（`CIPHER-VAULT-<版>-x64-setup.exe`）とportable版（`-portable.exe`）を作るだけで、公開はしません。版はルートの `package.json` から `tauri.conf.json` を通して入ります。portable版は、setupの中のexeにだけ付く印（bundle type）がないことを確かめてから書き出します。署名と `latest.json` の作成は[リリース手順](リリース手順.md)を参照してください。リリースビルドだけが必要な場合は `npm run build:tauri` を使います。

アイコンの原本と再生成は[手動更新とアイコン](手動更新とアイコン.md#アイコン)を参照してください。

## 変更に応じた検証

変更した範囲の試験を選びます。`npm run test:*` は必要なビルドを含みます。生成物が変わっていなければ、成功済みのビルドや試験を繰り返す必要はありません。

| 変更範囲 | コマンド |
|---|---|
| 中核（`crates/vault-core`）・デスクトップの外側（`apps/desktop`） | `npm run test:rust` |
| 画面のセッション処理・CSP・フォント | `npm run test:web` |
| 画面・CSP・IPCの許可と、画面からの保管庫操作 | `npm run test:tauri-shell` |
| 配布物・手動更新 | `npm run test:tauri-update`、配布物の構成は `npm run package:tauri` |
| 依存関係 | `npm run test:dependencies` |

画面変更はビルドだけで完了とせず、影響する操作と表示を確認します。単体・画面・配布物では検出できる不具合が異なるため、異なる層の試験を重複扱いで削除しません。試験は一時フォルダ・一時プロファイルを使い、利用中の保管庫を初期化・上書きしません。

暗号互換は、実装とは別のPythonで作った固定ベクトル（`tests/fixtures/crypto-compatibility.json`）を `crates/vault-core/tests/fixture_compat.rs` で照合します。期待値を実装から再生成して通さず、形式変更時は別実装との一致を確認してください。容量・nonce上限の試験には数百MiBの一時領域が必要です。

画面から呼べるコマンドは、`apps/desktop/build.rs` の一覧と `tauri.conf.json` の `capabilities` の両方に書いたものだけです。一覧に書かないと、Tauriは登録したコマンドをすべての画面に公開します。タイトルバーが使うTauri本体のウィンドウ操作は、`capabilities` に `core:window:allow-…` として個別に書きます（[設計](設計.md#画面から呼べるコマンド)）。画面のCSPは `packages/shared/src/renderer-policy.ts` と `tauri.conf.json` の `csp` を同じ文字列にします（`test:web` で照合）。

`test:web` は、世代をまたぐ応答の拒否や保守操作の取消など画面のセッション処理（`apps/web/src/lib/vault-client-session.ts` と `api.ts`）を、`window.passwordManager` を差し替えて確かめます。あわせて、ビルドした画面のCSPと `tauri.conf.json` の一致と、同梱フォントの取得元のハッシュとライセンスを確認します。

`test:tauri-shell` は `e2e` 機能付きでビルドし、WebView2のデバッグポートから実際の画面を操作します。`e2e` 機能付きのビルドは、環境変数 `CIPHER_VAULT_E2E_DEBUG_PORT` のポートと `CIPHER_VAULT_E2E_PROFILE` の一時プロファイルを、Tauriの設定としてWebView2へ渡します。`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` は、CIのrunnerでは反映されなかったため使いません。プロファイルは実行ごとに作って終了後に削除するので、インストール済みアプリのプロファイルには触れません。製品名が「CIPHER VAULT」のままの `e2e` ビルドが既定の保存先を開かないことと、利用中の保存先を指定した起動が拒否されることを確かめた後、一時フォルダを保存先にして、画面から初期設定・エントリの追加（パスワード生成を含む）・ロック・誤ったパスワードでの解除・解除を行い、保存したDBにパスワードが平文で含まれないことを確認します。続けて画面からバックアップを書き出し、項目を消した保管庫へ同じファイルを読み込みます（誤ったパスフレーズの拒否と、空でない保管庫への復元の拒否も確かめます）。その後、画面からパスワードの点検を開き、点数と件数を確かめます。画面から保管庫をv2へ更新し、前のパスワードが拒否され、新しいパスワードで開いた保管庫に同じ項目があること、保存先のどのファイルにもパスワードが平文で含まれないことも確かめます。続けて、画面のメニューからパスワードをコピーし、ロックでコピーが消えること、画面ロック・スリープ（復帰の2種類を含む）の通知で保管庫がロックされてコピーが消え、その間は正しいパスワードでも解除できないこと、コピーが30秒で消えること、同じ保存先で2つ目を起動するとすぐ終了すること、ウィンドウを閉じるとロック・コピーの消去・終了の順に進むことを確かめます。画面ロックとスリープの通知は、Windowsが送るものと同じウィンドウメッセージで模擬します。`e2e` 機能付きのビルドは保存ダイアログを出さず、環境変数 `CIPHER_VAULT_E2E_DOWNLOADS` の一時フォルダへ保存するので、実際の保存ダイアログは手で確認してください。同じく `e2e` 機能付きのビルドは偽のクリップボードを使い、利用中のクリップボードを上書きしません。実際のクリップボードへの書き込みと消去は `test:rust` の `clipboard_station` が専用のウィンドウステーション内で確かめます。実際の画面ロック・スリープ、貼り付け、クリップボード履歴（Win+V）は自動では確かめられないので、通常ビルドと合成データで手で確認してください。このビルドはsetupではないので、バージョンと更新の画面が配布ページだけを案内し、更新の確認・取得・適用を呼んでも何も起きないこと、更新プラグインが画面向けに用意するコマンドが拒否されることも確かめます。タイトルバーのボタンで最大化と元に戻すことができ、ダイアログを開いている間もメニューと一覧は操作できずにウィンドウのボタンは使えること、Escapeでダイアログが閉じることも確かめます。ウィンドウはタイトルバーの閉じるボタンで閉じます。あわせて、画面がTauri用のCSPで読み込まれること、IPCがTauri独自のプロトコル（`http://ipc.localhost`）で応答しpostMessageへ切り替わらないこと、外部への通信・画面遷移・新しいウィンドウ・画面が作っていないダウンロード・許可していないコマンドが拒否されることを確認します。スクリーンショットは `target/e2e-screenshots` に保存します。`e2e` 機能付きのビルドは配布しないでください。

`test:tauri-update` は、`e2e` 機能付きのsetupを版0.0.1と0.0.2で作り、実際に更新します。試験専用の製品名（CIPHER VAULT Update Test）と識別子でビルドするので、インストール済みのアプリとは干渉しません。署名鍵は実行ごとに一時フォルダへ作って捨て、ビルドは `target/update-check` に分けるので、ほかの試験のビルドも置き換えません。0.0.1をショートカットなしで一時フォルダへインストールし、合成データで保管庫と項目を1件作った後、ローカルのサーバーから、同じ版（更新なし）、古い版の署名を付けた新しい版と、正しい署名のまま中身を1バイト変えた新しい版（どちらも取得後に拒否）、正しく署名した新しい版を順に返します。未保存の編集の確認で戻ると何も変わらないこと、破棄を選ぶと保管庫をロックしてアプリが終了し、インストーラーが0.0.2として起動し直すこと、同じパスワードで同じ項目を開けることを確かめ、最後にアンインストールします。インストーラーは起動し直すときに元のアプリの引数だけを引き継ぎ、環境変数は引き継がないため、この試験では `e2e` 機能付きのビルドの設定を `--e2e-env=名前=値` の引数で渡します。試験中は、インストーラーが起動し直したアプリのコンソールのウィンドウが一時的に表示され、アンインストール情報とインストーラーの言語設定が `HKCU` に一時的に登録されます（終了時に消します）。配布用の鍵での署名とGitHubからの取得は、この試験では確かめられません。

実OS通知・実電源断・更新インストールの受入は、自動試験と分けて記録します。sandboxによるrename・junctionの拒否は実装の失敗と区別し、必要なら同じ一時データの試験を許可された環境で再実行します。

### Electron版から移植したときの確認

v0.9.0までは、移植の正しさを次の試験で確かめていました。どれもElectron版とNode.jsのサービスが必要なので、削除と一緒になくしました。タグ `v0.9.0` を取り出せば実行できます。

- `test:rust-parity`: 同じ呼び出しを `crates/vault-core` とTypeScriptのサービスへ与え、値またはエラーのstatusと文言を一つずつ比べる差分試験。
- `node_interop`: TypeScriptのcodecが書いた合成データを `crates/vault-core` で読めるかの確認。
- `test:tauri-migration`: 試験専用の製品名でElectron版のsetupをインストールし、Rust版のsetupがElectron版を削除して保管庫を残すことと、portable版を確かめる試験。

Electron版を削除するsetupのフック（`apps/desktop/windows/installer-hooks.nsh`）を変えるときは、タグ `v0.9.0` の作業ツリーに変更したフックを置いて `npm run test:tauri-migration` を実行し、Electron版からの移行が壊れていないことを確かめてください。

## CIと依存監査

`.github/workflows/ci.yml` はpush・PR・手動実行で起動します。同じリポジトリ・ブランチの重複実行は最新の1件にまとめます。Windows 2025 / Node.js 24で、次のジョブを実行します。

- 画面: `npm run test:web`
- Rust版: 画面をビルドしてから `cargo test --workspace --locked` を実行し、`e2e` 機能付きのビルドで `scripts/verify-tauri-shell.mjs` の実ウィンドウ検証を行います。Rustのツールチェーンはrunnerに含まれるものを使い、Cargoの依存は `Cargo.lock` に固定します。
- 依存監査: `node scripts/audit-dependencies.mjs`

ワークフローの権限は `contents: read`、checkout後の認証情報の保持は無効です。外部ActionsはコミットSHAで固定し、npmのダウンロードキャッシュだけを再利用します。配布物の生成・署名・公開、秘密の注入、DB・profile・クリップボードの成果物保存は行いません。インストール済みアプリの更新適用、実OS通知は、これらのジョブでは確認していません。

依存監査のスクリプトは `npm audit --package-lock-only --json` の結果を読み、npmの依存のlow以上と監査エラーを失敗とします。install scriptは実行しません。指摘は依存元・到達条件・修正版を確認し、未検証の除外や強制更新で通さないでください。修正版がなく、到達経路を確認できた指摘だけを、スクリプト冒頭の `accepted` に期限付きで登録できます。登録には脆弱性ID・パッケージ名・許可する親パッケージ・期限・理由を書きます。期限切れ、指摘が出なくなった場合、許可した親以外から到達する場合はCIが失敗するので、そのときは登録を見直すか削除します。現在の登録はありません。Rust依存の脆弱性監査はまだ自動化していません。

依存更新は、`npm explain <package>`・`cargo tree -i <crate>` とlockfileで親と実行経路を確認してから行います。`fixAvailable` だけを理由に強制更新せず、更新後に監査を取り直します。Viteのmajor更新は別の変更に分け、React plugin・Node.js要件を確認したうえで、CSP、フォント、`test:tauri-shell` を再検証します。`apps/web/vite.config.ts` の `build.target` はVite 5相当の `chrome87` / `edge88` / `firefox78` / `safari14` を明示し、ツール更新で出力目標が変わることを避けています。

## アイコンが古いまま見える

まず `build/icon.ico` を再生成して配布物を作り直します。正しいアイコンがexeに埋め込まれていても表示が古い場合は、Windowsのアイコンキャッシュの影響を切り分けます。
