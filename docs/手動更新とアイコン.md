# 手動更新とアイコン

## 利用方法

Windows の setup 版では、タイトルバーの「アプリ情報」から更新できます。ロック中でも利用可能です。

1. 「更新を確認」を押します。
2. バージョンと変更内容を確認し、「ダウンロード」を押します。
3. 「再起動して更新」を押すと保管庫をロックし、インストーラーを起動します。

未保存の入力があるときは「編集に戻る」で保存してから再試行するか、「破棄して更新」を選びます。保存処理中は更新を開始できません。
「あとで」はダイアログを閉じるだけです。通常終了でも自動適用しません。アプリを終了してから再び起動した場合は、もう一度手動で確認・ダウンロードを行います。ライブラリが有効なキャッシュを再利用する場合があります。
portable 版と開発モードでは配布ページへの案内を表示します。ブラウザ版にはアプリ内更新はありません。
更新機能のない旧版からは、最初の一回だけ新しい setup を手動でインストールしてください。

## 更新機能のない旧版からの移行

1. 既存の CIPHER VAULT を終了します。
2. 新しい setup を実行し、既存と同じインストール先へ上書きインストールします。事前のアンインストールは不要です。
3. 起動後、新しいアイコンと「アプリ情報」ボタンを確認します。

保管庫はインストール先とは別の `userData/data` に保存されます。更新のために保存先を変更したり、データを削除したりする必要はありません。
2026-09-15 に、利用者から更新機能のない旧版から今回の版への setup による移行完了の報告を受けています。確認時点のパッケージ番号は両方とも `0.1.0` です。この確認は、異なる公開バージョン間のアプリ内更新の検証とは別です。

## 配布時に必要なもの

- ルート `package.json` の `version` を公開する新しいバージョンに変更し、ロックファイルと揃えます。同じバージョンを再公開しても更新対象にはなりません。
- `npm run package:desktop` で配布物を作成します。このコマンドは公開しません。
- `Termnix-IT/CIPHER-VAULT` の公開 GitHub Releases に、バージョンに対応するタグで安定版を公開します。
- **同じビルドの setup.exe と latest.yml を必ず一緒に公開します。** 生成された setup 用 blockmap も添付します。portable.exe は補助配布物です。
- prerelease とダウングレードは対象外です。更新情報や成果物が不足している場合はエラーを表示します。
- `appId`、パッケージ名、`userData` の保存先を更新のために変更しないでください。DB はインストール先と分離されています。

更新処理は `electron-updater` を使用します。`autoDownload` と `autoInstallOnAppQuit` は false に固定し、手動操作時だけ API を呼び出します。チェックサム検証をライブラリに委ね、署名検証を無効にする設定は加えていません。現状、署名用の証明書はリポジトリには設定していません。署名は発行元を検証するためのもので、チェックサムだけでは同じ保証になりません。署名付き配布を行う場合は配布環境で証明書と発行元を設定してください。

## アイコン

原本は `build/icon.png` です。鍵と黒曜石の意匠を残した透過 PNG を内蔵 imagegen で生成しています。
生成指示の要旨：中央の銀色の鍵と黒曜石を維持し、結晶を大きな面に整理、反射と細部を抑え、小さくても読める半立体アイコンにする。文字と背景は入れず、透過 PNG とする。出力に描かれた背景を除去する追加指示を行い、アルファを確認済みです。

使用した生成指示（内蔵 imagegen、既存画像を参照して編集）：

```text
Edit this app icon for CIPHER VAULT. Preserve the central silver key and black obsidian crystal identity. Modern refined semi-3D app icon, simplify crystal into few large angular facets, reduce tiny cracks and mirror glare. Bold legible silver key silhouette with circular bow and simple teeth, centered upright on obsidian. Cool black graphite and restrained silver highlights. Single isolated icon fills 85% of square canvas with balanced margins. Genuine transparent background alpha, no gray backdrop, no checkerboard painted in image, no floor shadow, no text. Must remain recognizable at 24px. Output one final production icon.
```

透過を修正した追加指示：

```text
Background extraction edit. Keep this exact black obsidian and silver key icon. Remove the checkerboard completely. Output a PNG with actual transparent alpha outside the obsidian silhouette, NOT a visible checkerboard. No background pixels, no text. Preserve the icon shape and materials.
```

原本を変更したら、PowerShell で次を実行します。

```powershell
./scripts/build-icons.ps1
```

16 / 24 / 32 / 48 / 64 / 128 / 256 px を含む `build/icon.ico` と、画面・favicon 用 `apps/web/public/icon.png` を生成します。
exe のリソース編集は `signAndEditExecutable: true` で有効化しています。以前の false 設定では Electron の標準アイコンが残ります。正しい埋め込みを確認しても古いショートカットだけ表示が残る場合は、Windows のアイコンキャッシュを切り分けます。

この Windows 環境では、初回ビルド時に winCodeSign 同梱の macOS 用シンボリックリンクの展開が失敗しました。取得済みの公式 `winCodeSign-2.6.0.7z` をキャッシュの `winCodeSign/winCodeSign-2.6.0` へ、Windows で不要な `darwin` フォルダを除外して展開することで解消しています。別環境で同じ症状が出た場合の参考：[electron-builder issue #8149](https://github.com/electron-userland/electron-builder/issues/8149)。アイコン編集を false に戻す必要はありません。

## 検証

2026-09-15 時点の確認結果:

| 対象 | 結果 |
|---|---|
| 手動更新の制御テスト | 6件成功。自動実行の抑止、二重操作、キャンセル、エラー後の再試行を確認 |
| 画面操作 | 更新状態を模擬し、延期、未保存入力、変更内容の文字表示、最小ウィンドウサイズを確認 |
| Electron 実行 | テスト専用データで preload / IPC、アプリ情報、バージョン・画像表示を確認 |
| 配布ビルド | setup / portable の生成、exe のアイコン埋め込み、setup と更新メタデータの SHA-512・サイズ一致を確認 |
| 旧版から setup で移行 | 利用者から移行完了の報告あり |
| 公開リリース間のアプリ内更新 | 未検証。異なるバージョンで公開前に実施する |

```powershell
npm run test:updates
npm run build:desktop
npm run package:desktop
```

公開前にはテスト用の保管庫と2つの異なるバージョンで、旧版から新版への実インストール・再起動・保管庫の解錠・既存エントリの維持を確認します。通信失敗、破損ダウンロード、未保存編集のキャンセル、通常終了後に更新されないことも確認対象です。本番の保管庫で更新テストは行わないでください。
