# CIPHER VAULT 設計

## 設計方針

- ローカルファースト: 保管庫データは端末内の SQLite に保存する
- 単一ユーザー: マルチユーザー管理や外部認証を持たない
- UI と処理の分離: React UI から Web 版は HTTP、Electron 版は IPC で共通サービス層を呼び出す
- 依存関係を抑制: API は Node.js 標準 `http`、暗号処理は標準 `node:crypto` を使用する

## システム構成

```text
React UI
  ├─ Web: Fetch API → Node.js HTTP Router
  └─ Electron: preload → IPC handler
                         │
                         ▼
             共通サービス層
             ├─ Vault Service
             ├─ Entry Service
             ├─ Password Service
             └─ Crypto Service
                         │
                         ▼
                       SQLite
```

| パッケージ | 役割 |
|---|---|
| `apps/web` | React + Vite のユーザーインターフェース |
| `apps/api` | HTTP入口、SQLite、暗号化、保管庫・エントリ管理 |
| `apps/electron` | デスクトップウィンドウ、preload、IPC、クリップボード、手動更新 |
| `packages/shared` | Web・API・Electronで共有するTypeScript型 |

Web版とElectron版の詳細な経路は[ワークフロー](ワークフロー/02-Web・ElectronからSQLiteまで.md)を参照してください。

## 実行経路

### Web版

開発時はViteのプロキシが `/vault`、`/entries`、`/password` を `localhost:3001` へ転送します。本番時はNode.js APIがビルド済みのWebアセットも配信します。

### Electron版

`apps/web/src/lib/api.ts` が `window.passwordManager` の有無で実行環境を判定します。Electronでは `contextBridge` で公開したAPIからIPC handlerを経由し、APIと同じサービス層を直接呼び出します。

データベースはElectronの `userData/data` 配下に保存します。Web/API版は既定で `apps/api/data` を使用します。

## 保管庫と暗号化

手動更新の通信は保管庫操作とは分離しています。更新確認・ダウンロード時に GitHub へ接続しますが、保管庫データは送信しません。

### マスターパスワード

マスターパスワードそのものは保存しません。

1. 16 byteのランダムSaltを生成する
2. `scryptSync` で32 byteの保管庫鍵を導出する
3. 鍵をキー、固定ラベル `CIPHER VAULT password verifier v1` をメッセージとするHMAC-SHA256を検証値としてSQLiteへ保存する（鍵そのものは保存しない）
4. 比較には `timingSafeEqual` を使用する
5. 解錠中だけ保管庫鍵をプロセスメモリに保持する

手動ロックまたは5分間の無操作による自動ロックで、保持中の鍵Bufferをゼロ埋めして参照を破棄します。JavaScriptランタイム全体のメモリ消去を保証するものではありません。

この検証値の修正はv0.2.1から適用されます。v0.2.0以前は導出鍵そのものを検証値に保存していました。旧形式は正しいパスワードでの解除時に `kdf_params.verifierAlgorithm = "hmac-sha256-v1"` を追加し、検証値を置き換えます。暗号文と鍵導出方式は維持し、移行後は旧版で解除できません。失敗した認証では移行せず、移行の書き込みに失敗した場合も解錠しません。

SQLiteの `secure_delete` を有効にしますが、既存のバックアップ、ジャーナル、ファイルシステムの過去データの消去は保証しません。旧DBに含まれた鍵はこの移行で失効しません。詳細と対応範囲は [v0.2.1の修正](リリースノート/v0.2.1.md) を参照してください。

### エントリ暗号化

パスワードとメモはAES-256-GCMで個別に暗号化します。

```text
[ IV (12 bytes) | Auth Tag (16 bytes) | 暗号文 ] → Base64
```

サービス名、ログインID、URL、タグ、グループ、日時は検索・一覧表示のため平文で保存します。

## データモデル

### `vault_metadata`

保管庫の検証情報を `id = 1` の1行で保持します。

| カラム | 内容 |
|---|---|
| `password_salt` | 鍵導出用Salt |
| `password_verifier` | マスターパスワードの検証器 |
| `kdf_params` | KDFパラメータ |
| `created_at`, `updated_at` | 作成・更新日時 |

### `password_entries`

| カラム | 内容 | 保存形式 |
|---|---|---|
| `service_name`, `login_id` | サービス名、ログインID | 平文 |
| `encrypted_password`, `encrypted_notes` | パスワード、メモ | AES-256-GCM |
| `url`, `tags`, `group_name` | URL、タグ、グループ | 平文 |
| `created_at`, `updated_at` | 作成・更新日時 | 平文 |

## API

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/health` | ヘルスチェック |
| `GET` | `/vault/status` | 保管庫状態取得 |
| `POST` | `/vault/setup` | 初期設定 |
| `POST` | `/vault/unlock` | ロック解除 |
| `POST` | `/vault/lock` | ロック |
| `POST` | `/vault/reset` | 保管庫の完全リセット |
| `GET` | `/entries` | エントリ一覧 |
| `POST` | `/entries` | エントリ作成 |
| `GET` | `/entries/:id` | エントリ詳細 |
| `PUT` | `/entries/:id` | エントリ更新 |
| `DELETE` | `/entries/:id` | エントリ削除 |
| `POST` | `/password/generate` | パスワード生成 |

エントリ操作は保管庫の解錠を必要とします。一覧レスポンスにはパスワードとメモを含めず、詳細取得時だけ復号します。

## フロントエンド

```text
起動 → 保管庫状態取得
  ├─ 未設定   → LockScreen（初期設定）
  ├─ ロック中 → LockScreen（ロック解除）
  └─ 解錠済み → VaultDashboard
```

`App.tsx` が保管庫状態、エントリ一覧、選択中エントリ、自動ロックを管理します。画面固有の表示と入力は `pages/`、共通表示は `components/`、通信切替は `lib/api.ts` が担当します。

UIは「Black Ops Secure Terminal」をテーマとし、色・タイポグラフィ・アニメーションの定義は `apps/web/src/styles.css` に集約します。

## 手動更新とアプリ情報

`AppInfo.tsx` が共通タイトルバーから利用できる更新画面を提供します。`preload.ts` の専用 API から `update-service.ts` へ要求し、`ManualUpdater` が `electron-updater` の状態と操作を管理します。更新要求の IPC はメインウィンドウのメインフレームからの呼び出しだけを受け付けます。

Windows の setup 版向けに、確認・ダウンロード・適用を個別の操作に分けます。起動時の確認、ダウンロードの自動開始、通常終了時の自動適用はありません。未保存入力は更新前に確認し、保存処理中は適用ボタンを無効化します。適用時に保管庫をロックし、終了時に DB を閉じます。更新処理に DB スキーマ変更はありません。

更新状態はメモリに保持し、IPC イベントで UI に通知します。変更内容は HTML として解釈せず文字として表示します。通信失敗でも保管庫を利用できます。portable 版と開発モードは配布ページへ案内します。

画像の原本は `build/icon.png`、Windows 用は `build/icon.ico`、タイトルバー・アプリ情報・favicon 用は `apps/web/public/icon.png` です。
詳細は [手動更新とアイコン](手動更新とアイコン.md) と [更新フロー](ワークフロー/04-手動更新.md) を参照してください。
