# GitHub リリース手順

Windowsのsetup版を主配布、portable版を補助配布として、[GitHub Releases](https://github.com/Termnix-IT/CIPHER-VAULT/releases)で公開します。生成だけでは公開されません。

## 事前確認

1. ルート `package.json`・lockfile・リリースノートの版を揃えます。既存の公開版より大きい版を使います。
2. [変更に応じた検証](開発・配布手順.md#変更に応じた検証)を完了し、公開対象の変更を確定します。
3. リポジトリルートで配布物を生成します。ビルドも含むため、直前に同じビルドを繰り返す必要はありません。

```powershell
npm run package:desktop
```

## 配布物を確認する

`dist-desktop/` の同じビルドから、次を添付します。

| ファイル | 用途 |
|---|---|
| `CIPHER-VAULT-<version>-x64-setup.exe` | 通常利用・アプリ内更新 |
| `CIPHER-VAULT-<version>-x64-portable.exe` | インストール不要の版 |
| `latest.yml` | 更新情報 |
| `CIPHER-VAULT-<version>-x64-setup.exe.blockmap` | 差分ダウンロード用 |

`latest.yml` のsetup名・サイズ・SHA-512と実ファイルが一致することを確認します。ファイル名は空白を使わず、GitHubの添付名と完全に一致させます。配布物の同梱・除外と起動は `npm run test:desktop-package` で確認します。実更新の確認は[更新機能の検証](手動更新とアイコン.md#検証)に従ってください。

## 公開する

1. `Draft a new release` で下書きを作ります。タグは `v<version>`、対象は確定したリリース用コミット、タイトルは `CIPHER VAULT v<version>` とします。
2. 変更の要約と必要な互換性・移行の注意を記載し、上記の4ファイルをアップロードします。
3. タグのコミット、版、添付ファイルを確認して公開します。CLIでも下書き・添付確認後に公開します。

既存タグや公開済み資産は上書きしません。ベータ版にはprereleaseを指定します。アプリ内更新の対象は安定版だけです。

## Rust版への切り替え

Electron版からRust（Tauri）版への切り替えは、2つのリリースで行います。理由と仕組みは[設計](設計.md#rust版への移行)を参照してください。

1. **Electron版の最終版**: 上の手順のまま公開します。この版はアプリ内更新を行わず、「バージョンと更新」で配布ページだけを案内します。それより前の版は、アプリ内更新でこの版になります。
2. **Rust版**: 最終版より大きい版で、別のリリースとして公開します。GitHubの「最新リリース」がこのリリースに変わるので、Electron版の最終版の `latest.yml`・setup・`.blockmap` も添付し、まだ古いElectron版を使っている人が最終版へ更新できるようにします。

Rust版の配布物は、署名用の秘密鍵を環境変数で渡して作ります。秘密鍵とパスワードはリポジトリ・CI・チャットに置かず、公開する人の端末だけで扱います。

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "$HOME\.tauri\cipher-vault.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = Read-Host "鍵のパスワード" -MaskInput
npm run build:web:tauri
node scripts/package-tauri.mjs --notes <リリースノートのテキストファイル>
Remove-Item Env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

`dist-tauri/` の次のファイルを添付します。

| ファイル | 用途 |
|---|---|
| `CIPHER-VAULT-<version>-x64-setup.exe` | 通常利用・アプリ内更新・Electron版からの移行 |
| `CIPHER-VAULT-<version>-x64-portable.exe` | インストール不要の版 |
| `latest.json` | Rust版の更新情報（setupの署名とURLを含む） |

`latest.json` のURLは `https://github.com/Termnix-IT/CIPHER-VAULT/releases/download/v<version>/CIPHER-VAULT-<version>-x64-setup.exe` なので、タグとsetupの名前を変えずに公開します。`.sig` は `latest.json` に含まれるので添付は不要です。公開の前に `npm run test:tauri-migration` と `npm run test:tauri-update` を通し、手での受け入れ確認（[開発・配布手順](開発・配布手順.md#rust版移行中)）を済ませます。

## リリースノートとラベル

冒頭の2〜3行で利用者に見える変更を説明し、追加・改善・修正、必要な移行手順・既知の制約を記載します。変更のない分類は省きます。配布形式の説明は[README](../README.md#入手起動)へリンクできます。

`Generate release notes` の分類は [.github/release.yml](../.github/release.yml)が管理します。PRの内容に合うラベルを使い、公開ノートから除外する内部変更には `skip-release-notes` を付けます。
