# GitHub リリース手順

Windowsのsetup版を主配布、portable版を補助配布として、[GitHub Releases](https://github.com/Termnix-IT/CIPHER-VAULT/releases)で公開します。生成だけでは公開されません。

## 事前確認

1. ルート `package.json`・lockfile・リリースノート（`docs/リリースノート/v<version>.md`）の版を揃えます。既存の公開版より大きい版を使います。
2. [変更に応じた検証](開発・配布手順.md#変更に応じた検証)を完了し、公開対象の変更を確定します。`npm run test:tauri-update` も通します。
3. 手での受け入れ確認を、通常ビルドと合成データの保管庫（`CIPHER_VAULT_DATA_DIR` に試験用フォルダ）で済ませます。画面ロック・スリープでのロック、貼り付け、クリップボード履歴（Win+V）、バックアップの保存ダイアログを確認します。

## 配布物を作る

配布物は、署名用の秘密鍵を環境変数で渡して作ります。秘密鍵とパスワードはリポジトリ・CI・チャットに置かず、公開する人の端末だけで扱います。`--notes` のファイルの文章は、アプリの「バージョンと更新」に変更内容として表示されます。

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "$HOME\.tauri\cipher-vault.key"
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = Read-Host "鍵のパスワード" -MaskInput
try {
  # PowerShellはnpmやnodeの失敗だけでは止まらないので、終了コードを確かめて止める。
  npm run build:web
  if ($LASTEXITCODE -ne 0) { throw "画面のビルドに失敗しました" }
  node scripts/package-tauri.mjs --notes <更新画面に出す文章のテキストファイル>
  if ($LASTEXITCODE -ne 0) { throw "配布物の作成に失敗しました" }
} finally {
  Remove-Item Env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD, Env:TAURI_SIGNING_PRIVATE_KEY -ErrorAction SilentlyContinue
}
```

`dist-tauri/` の次のファイルを添付します。

| ファイル | 用途 |
|---|---|
| `CIPHER-VAULT-<version>-x64-setup.exe` | 通常利用・アプリ内更新・Electron版からの移行 |
| `CIPHER-VAULT-<version>-x64-portable.exe` | インストール不要の版 |
| `latest.json` | アプリ内更新の情報（setupの署名とURLを含む） |

`latest.json` のURLは `https://github.com/Termnix-IT/CIPHER-VAULT/releases/download/v<version>/CIPHER-VAULT-<version>-x64-setup.exe` なので、タグとsetupの名前を変えずに公開します。`.sig` は `latest.json` に含まれるので添付は不要です。公開の前に、`latest.json` の版・URLと、署名が `tauri.conf.json` の公開鍵で検証できることを確認します。

### Electron版向けの添付

まだElectron版のv0.7.0以前を使っている人がアプリ内更新でv0.8.0（Electron版の最終版）へ進めるよう、毎回のリリースにv0.8.0の次のファイルも添付します。Electron版は「最新リリース」に置かれた `latest.yml` を読み、そこに書かれたsetupを同じリリースから取得するためです。添付しないと、Electron版の更新の確認は失敗し、利用者は配布ページから手でsetupを入手することになります。v1.1.0以降は従来形式の保管庫を開けませんが、v0.8.0はその保管庫から `.cvault` を書き出せるので、添付を続けます。

| ファイル | 用途 |
|---|---|
| `latest.yml` | Electron版の更新情報（版は0.8.0） |
| `CIPHER-VAULT-0.8.0-x64-setup.exe` | Electron版の最終版 |
| `CIPHER-VAULT-0.8.0-x64-setup.exe.blockmap` | 差分ダウンロード用 |

公開済みのv0.8.0のリリースから取得して、そのまま添付します。中身を作り直さないでください。

```powershell
gh release download v0.8.0 --dir dist-tauri/electron-bridge --pattern latest.yml --pattern "CIPHER-VAULT-0.8.0-x64-setup.exe*"
```

## 公開する

1. 下書きを作ります。タグは `v<version>`、対象は確定したリリース用コミット、タイトルは `CIPHER VAULT v<version>` とします。
2. 本文にはリリースノートの見出しより後を使い、上記の6ファイルをアップロードします。
3. タグのコミット、版、添付ファイルを確認して公開します。CLIでも下書き・添付確認後に公開します。
4. 公開後、`https://github.com/Termnix-IT/CIPHER-VAULT/releases/latest/download/latest.json` と、`latest.yml` に書かれたsetupを取得できることを確認します。

既存タグや公開済み資産は上書きしません。ベータ版にはprereleaseを指定します。アプリ内更新の対象は安定版だけです。

## Rust版への切り替えの記録

Electron版からRust（Tauri）版への切り替えは、v0.8.0（Electron版の最終版。アプリ内更新を行わず、配布ページを案内する）とv0.9.0（最初のRust版。setupがElectron版を削除する）の2つのリリースで行いました。理由と仕組みは[設計](設計.md#electron版からの移行)を参照してください。

## リリースノートとラベル

冒頭の2〜3行で利用者に見える変更を説明し、追加・改善・修正、必要な移行手順・既知の制約を記載します。変更のない分類は省きます。配布形式の説明は[README](../README.md#入手起動)へリンクできます。

`Generate release notes` の分類は [.github/release.yml](../.github/release.yml)が管理します。PRの内容に合うラベルを使い、公開ノートから除外する内部変更には `skip-release-notes` を付けます。
