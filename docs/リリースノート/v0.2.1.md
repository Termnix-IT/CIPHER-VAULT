# CIPHER VAULT v0.2.1

保管庫の検証値と配布処理の問題を修正したリリースです。v0.2.0のsetup版はアプリ情報から手動更新できます。旧版から新しいsetupを上書きインストールする方法も利用できます。

## 保管庫の検証値

v0.2.0以前は、マスターパスワードの検証値としてAES暗号化鍵そのものをBase64でSQLiteへ保存していました。旧DBを取得した第三者がマスターパスワードなしでパスワード・メモを復号できる問題です。

修正後はNode.js標準のHMAC-SHA256で鍵から別の検証値を生成し、その値だけを保存します。新しい依存関係は追加しません。既存のScryptとAES-256-GCMを維持し、既存データをそのまま復号できます。

- 新規保管庫は最初から新しい検証値を保存します。
- 旧保管庫は正しいパスワードで解除した際に検証値を更新します。誤パスワードや移行書き込み失敗では解除しません。
- 移行後はv0.2.0以前で保管庫を解除できません。旧版で起動し直さないでください。
- 鍵自体の変更・既存エントリの再暗号化は行いません。過去のDBコピーやバックアップに残った鍵は引き続き既存暗号文を復号でき、新たに同じ保管庫で暗号化したデータにも使えます。
- SQLiteの削除領域消去を有効にしますが、過去のジャーナル、バックアップ、ストレージ上の残留データの完全消去は保証しません。
- 旧DBが他者に渡った場合、この移行だけでは対応が完了しません。保管していた各サービスのパスワード変更と、新しい保管庫への移行が必要です。既存の保管庫やバックアップを自動削除する処理はありません。

実際の利用中DBには検証を行わず、一時DBで新規作成、旧形式の移行、誤パスワード、移行書き込み失敗、既存パスワード・メモの復号、再ロック後の解除を確認します。

## その他の修正

- AGENTS.mdをElectron・IPC・手動更新を含む現行構成へ更新し、サービスの責務、検証コマンド、データ保護を整理。
- Web/API用配布スクリプトによる開発用DBの混入を解消。既存の `release/data` にファイルがある場合は停止し、削除を防止。この問題は `npm run package` の経路であり、Electronの配布設定は開発用DBを対象としていません。
- nullや誤った型の入力、不正JSON、小数のパスワード長を400エラーに統一。
- 静的ファイルの配信範囲を実パスで確認し、ディレクトリの読み込みやストリームエラーによるプロセス終了を防止。PNG・ICOのContent-Typeも修正。
- クエリ付きAPIのルーティングと不正URLの例外処理を修正。
- SQLiteの列追加で全エラーを握りつぶさず、既存列の有無を確認。
- 自動ロックの通知が状態再取得で消える問題を修正。
- SQLiteジャーナルをGitの除外対象へ追加。

## 確認コマンド

```powershell
npm run build:desktop
npm run test:api
npm run test:updates
```

`test:api` はElectron用にビルドされたbetter-sqlite3とPowerShellを使用し、一時ディレクトリを作成・削除します。配布スクリプトも一時フォルダへコピーして検証します。

2026-09-15: デスクトップビルド、API回帰テスト6件、手動更新テスト6件の成功を確認しました。実際の利用中DBへの適用と画面上での5分待機確認は行っていません。

設計根拠: [Node.js HMAC](https://nodejs.org/api/crypto.html#cryptocreatehmacalgorithm-key-options)、[SQLite secure_delete](https://www.sqlite.org/pragma.html#pragma_secure_delete)、[SQLite table_info](https://www.sqlite.org/pragma.html#pragma_table_info)。
